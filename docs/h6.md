# HU-6 — Valoraciones

## Objetivo

HU-6 agrupa las funciones de calificación de una sesión, consulta de reseñas de un tutor, administración de las calificaciones emitidas por el estudiante y ranking de tutores. La planificación funcional describe estos apartados:

- **6.1 — Calificar una sesión:** puntaje general, puntajes por aspecto y comentario.
- **6.2 — Reseñas en la ficha pública del tutor:** promedio, distribución, aspectos y comentarios filtrables.
- **6.3 — Mis calificaciones:** consulta, edición y eliminación dentro del plazo permitido.
- **6.4 — Ranking por curso:** consulta de tutores ordenados por valoración.

La implementación actual utiliza datos de ejemplo locales. No hay API ni base de datos conectada para guardar cambios de forma permanente.

## Navegación

Las páginas se conectan desde [App.jsx](../src/App.jsx):

| Ruta | Página | Uso |
|---|---|---|
| `/calificar` | `CalificarSesion.jsx` | Formulario para calificar una sesión. |
| `/tutor/:id` | `FichaTutorReseñas.jsx` | Ficha pública de reseñas del tutor indicado por `id`. |
| `/mis-calificaciones` | `MisCalificaciones.jsx` | Listado personal de valoraciones. |
| `/tutores` | `Directorio.jsx` | Pestañas **Todos los tutores** y **Ranking por curso**. |
| `/ranking` | Redirección a `/tutores?vista=ranking` | Enlace compatible para abrir directamente la pestaña Ranking por curso. |

En [DetalleTutor.jsx](../src/pages/DetalleTutor.jsx), el enlace **Ver reseñas** navega a `/tutor/${id}`. La ruta entrega el ID a `FichaTutorReseñas` mediante `useParams`.

Dentro de `/tutores`, la selección de la pestaña se refleja en el parámetro de URL `vista`. La pestaña del ranking se abre en `/tutores?vista=ranking`, por lo que se puede enlazar o recargar sin perder esa selección. **Todos los tutores** elimina ese parámetro y conserva el listado existente.

## Estructura del archivo de valoraciones

Cada elemento de `ValoracionMock.json` tiene esta forma:

```json
{
  "idCalificacion": 1,
  "idSesion": "SES-001",
  "idTutor": 101,
  "nombreTutor": "Carlos Mendoza",
  "curso": "Cálculo II",
  "puntajeGeneral": 5,
  "aspectos": {
    "claridad": 5,
    "puntualidad": 5,
    "dominio": 5
  },
  "comentario": "Excelente explicación, resolvió todas mis dudas para el parcial.",
  "fecha": "2026-10-15"
}
```

Los puntajes son valores del 1 al 5. La fecha se guarda como `AAAA-MM-DD`; las páginas la formatean para mostrarla a las personas.

## Relación entre valoraciones y perfiles de tutor

El `idTutor` del JSON no coincide con el `id` de `tutores.json`, así que `FichaTutorReseñas.jsx` mantiene una correspondencia explícita:

| `idTutor` en valoraciones | Tutor en el directorio |
|---:|---|
| `101` | `u-001` — Anita Alvarado Hancco |
| `102` | `u-002` — Camila Quispe Andrade |

Esta relación está definida en `ID_TUTOR_POR_ID_VALORACION`. Cuando se agreguen tutores o valoraciones, hay que actualizarla o reemplazarla por IDs compartidos en ambos archivos. En las reseñas solo se puede mostrar el nombre del autor si ese campo existe en los datos; actualmente el JSON no guarda dicho nombre.

## Cómo se calcula la ficha pública (6.2)

1. `useParams()` obtiene el ID de `/tutor/:id`.
2. `useTutores()` proporciona los perfiles. Mientras se cargan, se muestra un mensaje; si no existe el ID, se ofrece volver al directorio.
3. Se filtran las valoraciones cuyo `idTutor` mapea al ID de la URL.
4. El promedio se calcula como la suma de `puntajeGeneral` dividida por el número de valoraciones encontradas. Si no hay valoraciones asociadas, se usa como respaldo el promedio del perfil.
5. El total mostrado es el número de valoraciones encontradas; si no hay ninguna, se utiliza el total guardado en el perfil.
6. La distribución cuenta cuántas valoraciones tienen cada puntaje de 1 a 5. Las barras usan ese conteo dividido por el total de valoraciones encontradas.
7. Los promedios de claridad, puntualidad y dominio se calculan a partir de las valoraciones encontradas.
8. El selector **Puntaje: todos** filtra la lista por el puntaje seleccionado. El enlace de retorno abre la ficha del tutor.

La pantalla muestra datos reales del mock disponible, no comentarios inventados para completar el total del perfil.

## Ranking por curso dentro del directorio (6.4)

El ranking forma parte de la página `/tutores` y comparte la lista de tutores activos obtenida con `useTutores()`.

1. Las pestañas **Todos los tutores** y **Ranking por curso** cambian la vista en el propio directorio.
2. `vista=ranking` en la URL mantiene seleccionada la segunda pestaña al recargar o compartir el enlace.
3. Se incluyen tutores activos cuyo `perfilTutor.totalResenas` sea al menos cinco, de acuerdo con el umbral funcional de la planificación.
4. El filtro por curso compara el código seleccionado con los cursos de `perfilTutor.cursos`; el filtro de carrera compara con `tutor.carrera`. El curso inicial es `MA101` y la carrera inicial es **todas**.
5. Los resultados se ordenan por `perfilTutor.promedio` de mayor a menor. Si hay empate, se ordenan alfabéticamente por nombre completo.
6. Cada fila muestra posición, nombre enlazado a la ficha del tutor, carrera, cursos, modalidad, estrellas, promedio y cantidad de calificaciones.
7. Si no existen resultados para los filtros seleccionados, se muestra un mensaje de lista vacía.

El ranking usa los promedios y totales agregados del perfil en `tutores.json`; no recalcula el requisito de cinco valoraciones a partir del contenido de `ValoracionMock.json`. La ruta `/ranking` redirige a la pestaña del ranking dentro del directorio. El anterior componente independiente `RankingTutores.jsx` ya no es el origen de la vista integrada.

## Cómo funciona «Mis calificaciones» (6.3)

`MisCalificaciones.jsx` inicializa su estado con el import de `ValoracionMock.json`.

- **Filtro por curso:** se crea una lista sin duplicados de cursos existentes y se muestran solo las valoraciones del curso seleccionado.
- **Plazo de edición:** `DIAS_PARA_EDITAR` es 7. `sePuedeEditar()` compara la hora actual con el final del séptimo día posterior a la fecha de la valoración. La tarjeta muestra la fecha límite o **Plazo de edición vencido**.
- **Edición:** `iniciarEdicion()` copia puntaje y comentario al borrador; el formulario permite modificarlos; `guardarEdicion()` actualiza la valoración en el estado local y cierra el formulario.
- **Eliminación:** `handleEliminar()` pide confirmación y filtra el registro del estado local.
- **Persistencia:** guardar o eliminar modifica solamente el estado React. Al recargar la página, el JSON original se vuelve a cargar, por lo que los cambios se pierden.

## Alcance pendiente / consideraciones

- `CalificarSesion.jsx` todavía solo registra la evaluación en consola y muestra un `alert`; no la persiste ni queda disponible en las otras vistas.
- Las ediciones y eliminaciones de `MisCalificaciones.jsx` viven solo en memoria y se pierden al recargar.
- El ranking integrado usa los totales y promedios mock de `tutores.json`; no se recalcula desde todas las calificaciones individuales porque el archivo `ValoracionMock.json` solo contiene dos registros.
- Los valores agregados de perfil en `tutores.json` pueden representar más reseñas que las que contiene el mock. Si existen valoraciones relacionadas, la ficha calcula el promedio y la distribución solo con las que están en `ValoracionMock.json`.
- Para persistencia real y sincronización entre pantallas se requiere un backend o una capa de almacenamiento compartida.

## Prueba manual

1. Ejecutar `npm.cmd run dev` desde la carpeta `PROYECTO`.
2. Abrir `/calificar` para revisar el formulario.
3. Abrir `/tutores`, seleccionar un tutor y pulsar **Ver reseñas** para probar `/tutor/:id`.
4. Abrir `/mis-calificaciones` para filtrar, editar o eliminar las valoraciones de ejemplo.
5. En `/tutores`, seleccionar **Ranking por curso**, probar los filtros de curso y carrera y confirmar que el orden va de mayor a menor promedio.
6. Abrir `/ranking` y comprobar que redirige a `/tutores?vista=ranking`.
